# Remaining Fragkos cases under ten seconds

The six earlier 100-period instances remain development data. The evaluation set consists of every other author instance in section 6.5, with 44 cases over five item-count strata. The raw public archive and conversion rules are unchanged. The SHA-256 of the remaining conversion manifest is `b263139c1a2a92cd9fad5a12a39f41dfbd229229433eccb356ee6246f3d5b949`. Report every case and retain failures. Published long-budget incumbents may supply objective context after evaluation. [Author supplement](https://pubsonline.informs.org/doi/suppl/10.1287/ijoc.2016.0691) · [Remaining input lock](fragkos_source/remaining_instances/conversion_manifest.json)

Use the four existing whole-model arms (protected cold, external fallback, full warm start, explicit objective bound), the same input-only initializer, and an overlapping-window fix-and-optimize comparator. The window comparator frees setup decisions in the current window and reoptimizes continuous decisions over the full linked horizon, starting from the shared feasible plan. Compare its fixed order with an independently generated score that ranks the same windows using cost, capacity, and purchased opening stock. The window count, width, stopping code, checkpointing and solver budget are shared. Seal both programs and the generated policy before they see the remaining cases. [Prior inventory-guided windows](https://doi.org/10.1016/j.ejor.2011.11.036) · [Prior fix-and-optimize](https://doi.org/10.1016/j.ijpe.2009.08.022)

Each run has a ten-second process limit and a separate two-CPU scope with the original weighted objective. A counted output requires normal exit and the pinned checker. Compare the two window arms first on validity, then on paired cost. Report the complete win/tie/loss counts using `max(0.01, 1e-6 × comparison cost)` as a numerical tie tolerance. Also report pairs differing by at least 1% and the median paired relative change, and compare against the strongest existing arm. Within-set results are descriptive. Stratify by item count. For diagnostics, a positive cumulative demand-workload deficit before setup time certifies that some paid opening stock is necessary. Decompose cost changes into opening and operating costs, and compare the number of completed windows. The prior literature already uses stock to select windows. Any claimed advantage of the generated ordering requires evidence against the shared fixed-order solver and later comparison with a stock-only ordering.
