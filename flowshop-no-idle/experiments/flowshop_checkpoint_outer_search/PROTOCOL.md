# 检查点求值的等 CPU 外层排序试验

在固定作业排列内，最坏工期在新增机器无空闲约束的预算内精确求值。外层搜索调整作业排列。试验检验用已经验证的机器检查点图替换原作业位精确求值之后，同 CPU 时间能否找到更好的鲁棒排列。

公开组使用已见过的 Ruíz `large_instance_1`、`large_instance_3`、`large_instance_5`。按公开 `feasibility_check.py` 只取 `processing_times[j][i]` 中 `0≤j<n_jobs`、`0≤i<n_machines` 的活动前缀，并验证原文件哈希。原实例的无空闲标志仅属于其官方任务。两组本试验统一令中间机必须无空闲，其余内部机是可能的新增锁。三个独立合成矩阵依次使用种子 `2026112711`、`2026112712`、`2026112713`，分别为 63×11 独立整数均匀工时、89×14 作业机位交互、89×14 两机器瓶颈。新增锁预算分别为至多 2、3 台。各设定在首次运行前冻结。数据含派生鲁棒设定，无封存访问。

共同起点沿用前轮鲁棒规模复验的三种 NEH 锚点。以旧精确求值选出起始排列和情景库，所有方法共用，检查点也验证该起点。提案沿用每轮 24 个插入或交换、轮首强制跳转、严格改进和共用种子。每一矩阵和新增锁预算用同一个配对种子跑两个 CPU 上限 0.15、0.45 秒。同条件下按三种方法轮转顺序，跨截止的原子评分丢弃结果。

1. **作业位筛选精确**沿用前轮精确拒绝筛选算法和原单位代价最坏锁 DP。
2. **检查点筛选精确**沿用相同的筛选逻辑，将通过筛选的原子评分换成逐排列构图和检查点稀疏精确路径计算。构图计入每次搜索 CPU。存在并列最坏机集合时两种方法可返回不同见证，从而筛掉不同的失败提案。
3. **自适应四情景**保留最多四个已知最坏情景，每轮用原作业位精确 DP 核验两个最佳代理提案，沿用前轮强基线。

主对比为检查点筛选对作业位筛选的逐矩阵相对最坏工期改善率，分来源、锁数和 CPU 上限报告均值、胜平负、提案数、精确调用数和实际 CPU。自适应法是第二对照。之前的实用门槛为平均改善至少 1%，且来源组同向。固定提案对照另运行两轮 48 个提案，核验两精确臂的已接受排列轨迹和最后工期完全一致。所有输出排列均用独立前向排程递推枚举满预算锁集合核验，单个返回最坏场景也重评分。因工期对约束单调，枚举满预算等价于核验至多预算的最大值。共同初始化、固定提案核验和末态独立复算不计入等 CPU 搜索。运行单进程 WSL 逻辑 CPU 22，物理核 11，配对 sibling 为 23。
