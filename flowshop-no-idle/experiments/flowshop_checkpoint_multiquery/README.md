# 检查点图的固定排列多查询复验

此前约 25.5 倍的冷启动加速在更大的独立配对中保留了相近量级。九个矩阵上，检查点稀疏法在较大预算的单查询中，相对作业位稀疏法的含预计算加速为 **14.76–44.68 倍，中位 23.43 倍**。小预算时中位仍有 **6.39 倍**。三个不同费率共用一次建图，连同固定费率预算扫描的整批中位加速为 **61.27 倍**。这里的作业位基线也预存加工前缀，并使用一次最大预算的终点前沿回答同费率的全部查询。 [冻结协议](PROTOCOL.md) · [全部原始输出](results.json)

## 工期口径和验证

Ruíz 1 的共同基准工期为 5,849。对同一费率的预算 2、5、10、15，最坏绝对工期依次为 6,346、6,649、6,870、7,049，相应净增为 497、800、1,021、1,200。所有算法返回的都是同一固定排列的最坏值。前沿中的费用保持原始整数精度。

54 个不同预算与费率查询的最优值均由独立作业位密集 DP 或直接穷举核对。大整数容量验证穷举了 742 个可行锁集合；所有求值方法的 51 个不同返回见证均用独立前向排程重评分。三个带前沿返回的适配器调用原有转移，只为多查询保留终点前沿；作业位法额外把每行前缀移到共享预处理。相关源文件及冻结协议哈希在 JSON 中。

计时在预先协调的逻辑 CPU 26、物理核 13 上单进程执行，含验证共 11.892 秒 CPU。公开组取 checker 声明的工时前缀并沿用派生中间锁，费率均为本轮构造。结果验证的是固定排列下的精确多查询速度。未访问封存实例。 [checker](../../antigravity/data_confirmatory/ruiz2007/feasibility_check.py)
