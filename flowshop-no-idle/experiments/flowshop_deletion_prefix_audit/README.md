# 只用强制锁扫描的时钟删除阈值算法

独立实现通过 180 个随机工时矩阵、4,304 个删除与预算查询、10,223 次阈值测试。对 11,817 组全版与减版排程直接枚举工序。5,919 个正见证在返回路径的每一机器检查点均通过复算。其中 301 个见证包含零费用附加锁，176 个跨越种子与末机之间的强制锁。夹具还覆盖只含末机、空删全保及 401 位整数时刻。 [独立实现](validate_prefix.py) · [原始结果及代码摘要](results.json)

## 统一阈值

令 \(F\) 为强制锁集合。两种排程中都把末机视为强制锁，工期口径保持一致，因为末作业的前缀最大值就是该机的全行最大值。设 \(Z_0(j)\) 和 \(R_0(j)\) 分别为全版和减版在只取 \(F\cup\{j\}\) 时的机器 \(j\) 开工时刻。两者各用一遍只执行 \(F\) 的向量扫描即可得到。到达 \(j\) 时记录假定锁 \(j\) 的标量。若 \(j\) 是可选点，继续向下游传递其开放向量。

给定一个已实现的锁路径前缀，设它在锁定机 \(i\) 上的实际减版开工时刻为 \(x_i\)，已存的全版下界为 \(z_i\)，且 \(z_i\ge x_i+d\)。从 \(i\) 延至本段下一个实际锁点 \(j\)，所有中间机器开放。令 \(a(i,j)\) 为无局部时钟的齐次增量，\(b(i,j)\) 为该边保留局部时钟的最大贡献。实际减版开工为

$$x_j=\max\{x_i+a(i,j),b(i,j)\}.$$

传播下界 \(z_j=z_i+a(i,j)\) 已超过第一项至少 \(d\)。另一方面，

$$b(i,j)\le R_0(j)\le x_j.$$

第一个不等式成立，因为本段只执行强制锁的减版扫描包含 \((i,j]\) 内所有保留源，且这些源经过同样的开放后缀；最后的假定锁点也包含本机保留时钟。第二个不等式来自锁定的逐点单调性。锁定将每道工序的前缀最大值扩大为全行最大值，移除先前可选锁无法推迟任何下游操作。于是 \(z_j\ge R_0(j)+d\) 蕴含 \(z_j\ge x_j+d\)，反向由 \(R_0(j)\le x_j\) 直接得到。

因此同一费用的所有前驱都有同一阈值，保留最大齐次报价即可。已有的[反 Monge 性质](../flowshop_monge_budget/PROOF.md)适用于仅含实际机器的弧，线上二分上包络可在每个已付费用维护一份。虚拟首点无成功历史，算法不查询以它为起点的齐次弧。

## 滚动种子与回溯的正确性

若 \(Z_0(j)\ge R_0(j)+d\)，可在 \(j\) 以 \(Z_0(j)\) 开启状态，只付 \(j\) 的可选锁费用。种子代表一条具体的可行前缀。所有较早的机器只服从 \(F\)，其全版与减版开工时刻恰是两个扫描值。后来加锁无法向上游改变这个前缀。后续齐次传播给出同一见证的全版开工下界，因为全版的新增时钟只能推迟开工；统一阈值保证该下界仍高于该见证的实际减版。末机的作业占用前缀在两版相同，开工差直接给出工期差。回溯按机器是否属于强制集合纳入附加锁，因而能够保留零费用锁。

完整性从一条真正达到阈值的排程出发。对固定锁路径，工期是入口和各局部时钟贡献的最大值。若全版比减版大至少 \(d>0\)，可选一个达到全版末工期的被删源。其从来源起第一个遇到的实际锁点 \(j\) 包含免费末机。该源在 \(j\) 后沿齐次弧传递；一旦在任一后续锁点比减版少于 \(d\)，减版自身的齐次传播会保持这一差距上界，故不会在末机重新达到 \(d\)。删除 \(j\) 前所有可选锁不会改变该源到首锁 \(j\) 的传播，只会让减版更早。此时该源在 \(j\) 的开工贡献已被 \(Z_0(j)\) 吸收。以更大的扫描值作为种子、保留 \(j\) 以后原有锁点，即可沿余下路径达到阈值，费用也不会增加。

见证中的开工下界可来自早于当前强制区段的任意局部时钟。手核夹具删除机器 0 的时钟，保留强制机器 1 和末机 5。种子位于机器 2，其全版扫描开工值为 12，其中包含从机器 0 越过强制机器 1 的影响。候选机器 2 的费用为 0，机器 4 的费用为 1。加两锁后，全版与减版工期为 25 和 24。空集和各单锁两版都是 24。预算 0 无法达到阈值 1；预算 1 返回锁集 \(\{2,4\}\)，沿机器 2、4、5 的全版下界为 12、19、20。 [夹具工时、扫描及回溯](results.json)

## 预计算范围

预处理保存局部行向量、实际机器的齐次弧和全版扫描 \(Z_0\)。齐次弧跨删除、费用与预算查询共用，构建需 \(O(m^2n)\) 算术操作及 \(O(m^2)\) 表空间。该表依赖处理和换型时长、运输与提前量、强制锁位置。所有绝对局部时钟只出现在逐行输入、\(Z_0\) 和减版扫描 \(R_0\)。连入口向量也只用于扫描，虚拟入口弧不进入表。固定时钟配置下，每个删除查询额外花 \(O(mn)\) 构造 \(R_0\)，阈值试探间复用。无需存每个来源到每个目的点的稠密贡献，也无需存每个前驱和端点间的保留时钟表。

每个阈值的包络工作为 \(O(m(B+1)\log(m+1))\)，与保留时钟机器数无关。该界使用非负整数费用和预算、固定作业排列、逐机删除整个本地时钟向量、以及已有的后缀齐次反 Monge 性质。测试阈值 \(d\) 为正整数。最大误差可在一个有效上界内二分，并在阈值试探间共用扫描与弧。本文的复跑用可行锁集穷举给出真值，并分别检查真值及其下一整数阈值。

## 复跑

独立代码只复用已有的 `Envelope` 数据结构。验证用逐工序的开始约束与完工时间递推计算全版和减版真值，与实现的归一化前缀向量分开。输出包含脚本和数据结构源码的 SHA-256。运行在逻辑 CPU 0，原版约用 0.32 CPU 秒。大整数夹具以十进制字符串记录，使常用 JSON 解析器可以保留全部位数。

```bash
taskset -c 0 /usr/bin/python3 -B experiments/flowshop_deletion_prefix_audit/validate_prefix.py --output /tmp/flowshop-prefix-audit-replay.json
cmp experiments/flowshop_deletion_prefix_audit/results.json /tmp/flowshop-prefix-audit-replay.json
```
